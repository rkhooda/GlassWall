# SECURITY

GLASSWALL lets a remote language model drive a browser without letting it see what the
page contains. This document says how, says what it does not do, and names a file and
a check for every claim so the claims can be verified rather than trusted.

Numbers come from `eval/reports/summary.md` and `eval/reports/leakage.md`, generated by
`pnpm bench:all` and `pnpm bench:leakage` against the real extension in Chromium.

## What we do not guarantee

**N1. Perfect recall.** Deterministic recognizers cover checksummed identifiers, labelled
values and sensitive inputs; a BERT NER model covers names and places in prose. Prose
that names a person or a place in a way the model does not recognise can pass. The
mitigation is structural: the extractor never reads values, unexplained regions are
withheld, and the egress gate refuses anything that still matches a known secret.

**N2. Non-inference.** A sanitized observation still carries structure: page type, field
count, which fields are filled, quantized geometry. We do not claim differential privacy.

**N3. Malicious-page immunity.** Prompt injection is mitigated, not prevented. A page can
waste steps and can try to steer the planner. See the section below.

**N4. A benign reasoner.** If the model is hostile it emits hostile actions. The
validator and the confirmation modal are defence in depth, not a proof.

**N5. Side channels.** Payload size, step count and timing carry information.

**N6. Another extension in the same profile.** The vault lives in `chrome.storage.session`,
unreadable by web pages but readable by an extension with storage access. The
mitigation is lifetime: values exist only during a run.

## Threat model

| | Adversary | In scope | Control |
|---|---|---|---|
| A1 | Curious or compromised model provider | yes | handles-only observation, redacted pixels, egress gate (G2, G8) |
| A2 | Network observer | yes | a payload that holds nothing sensitive by construction; TLS is a deployment matter, the gateway is `localhost` here |
| A3 | Malicious web page | yes | structured observation under an untrusted-content wrapper, validator, origin check on NAVIGATE, confirmation on high risk |
| A4 | Buggy or adversarial planner output | yes | schema validation at the gateway and the client, freshness and identity binding, type-matched vault binding, literal scan, step budget, loop detector |
| A5 | Our own code leaking by accident | yes | one `fetch`, branded `SafePayload`, value-blind extractor, leakage canary with a negative control |
| A6 | Another extension reading session storage | partial | lifetime only (N6) |
| A7 | Compromised OS | no | none |
| A8 | Re-identification from structure | acknowledged | URL templating, quantized geometry (N2) |

## The three layers

1. **Construction.** The extractor emits structure, labels and text, never values.
   Inputs carry a `value_state`, not a value. Cookies and storage are never read.
2. **Detection and tokenization.** In `sanitize()`: element rules (`type=password`,
   `autocomplete`), checksummed recognizers (Aadhaar with Verhoeff, cards with Luhn,
   PAN, IFSC, GSTIN, UPI, email, phone, DOB, IP), label context (`dt/dd`, `Label: value`,
   table columns), then NER over DOM text and OCR over pixel regions the DOM cannot
   explain, fused by noisy-OR. Every detected value is registered in the session
   registry and replaced by a typed handle; the value goes to the session vault. Regions
   nobody can account for are withheld (explain-or-redact).
3. **The gate.** `egressGate()` re-validates the whole request: strict schema, a
   recognizer sweep over every released string, a registry scan in nine encodings, an
   entropy check for keys, size, rate, and the destination pin. Any failure aborts the
   step; nothing is stripped and retried.

Tier-1 types (password, CVC, OTP, card, secret) are decided by deterministic rules and
emit `⟦PASSWORD⟧` with no index; no model score is consulted.

## Prompt injection: mitigation, not prevention

- No raw HTML reaches the model; page text arrives inside typed JSON under an
  `untrusted_page_content` wrapper with instruction/data separation restated each turn.
- The validator, not the model, decides what runs: stale observation, unknown or
  changed element, hidden or disabled target, unsupported action, cross-origin
  navigation, mismatched vault type and secret-bearing literals are all refused.
- Payment, deletion and external navigation ask the user.
- Three refused actions in a row end the run; the gateway's loop detector ends runs
  that repeat without effect.

`GLASSWALL_DEMO_HIJACKED=1` makes the gateway's first provider a simulated hijacked
planner that types the Aadhaar handle into the search box; the client blocks it with
`VAULT_TYPE_MISMATCH` (`hijacked.ts`, DEMO beat 6).

## Failure matrix

Each row is a test in `apps/extension/src/background/orchestrator.test.ts`,
`eval/leakage/chaos.test.ts` or the privacy suite. "Fail-closed" means more redaction
and a smaller payload, never less.

| Failure | Behaviour | Direction |
|---|---|---|
| Gateway unreachable | run ends with `GATEWAY_UNREACHABLE`, red banner names the origin | closed |
| Provider error, key expired, garbage answer | gateway fails over: configured providers → scripted planner; one repair retry per provider | degrades |
| NER model missing or throws | every text node marked unexplained and withheld; `degraded` names the source | closed |
| OCR missing, timeout, or over budget | crops masked, not passed | closed |
| Offscreen document dead | both sources report failure; sanitize masks their coverage | closed |
| `sanitize()` throws | maximally redacted observation, `sanitize_exception` | closed |
| Gate violation | step aborts, audit written, the loop re-observes; three in a row end the run | closed |
| Content script gone (navigation mid-action) | treated as an observed navigation; next step re-injects | degrades |
| Restricted page (`chrome://`) | `NO_WEB_TAB` before any request | closed |
| Confirmation not answered in 90 s | treated as denied | closed |
| Abort during a network wait | run ends at the next check; the pending confirmation is denied | closed |
| Vault handle mismatched or unknown | `VAULT_TYPE_MISMATCH` / `HANDLE_NOT_FOUND`; nothing typed | closed |
| Previous run's values | the vault is cleared at the start and end of every run | closed |

## Residuals

1. The local gateway is `http://localhost:3000` without TLS. A deployed gateway should use TLS and an appropriate access-control boundary.
2. `BALANCED` needs a per-origin host permission to capture pixels; the panel asks on
   Start. `STRICT` needs none.
3. No trained face or visual-PII detector. Image regions without a DOM owner are masked
   wholesale; a detector is an extension point (`MODEL_CARD.md`).
4. Handles are per-session sequence numbers, not HMACs. They carry no value-derived
   material at all, which is the stronger property; a handle is stable within a session
   and meaningless outside it.
5. The provider chain is configured on the gateway, not the client; a deployment must
   trust its own gateway.

## Reporting

The useful form of a security report is a failing test in `eval/leakage/` or
`packages/privacy/src/*.test.ts`. Please include the affected boundary and a minimal
reproduction when reporting an issue.
