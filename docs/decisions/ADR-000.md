# ADR-000: Two-Person Team Scope Cuts (Pre-applied)

**Date:** 2024-08-28
**Status:** Accepted
**Deciders:** A (Agent & Control), B (Perception & Privacy)

## Context

The GLASSWALL project (SIH26171) was originally scoped for a 5–6 person team over ~15 days (PLAN.md §5.3). We are a 2-person team. Attempting the full scope would result in a broken `main` branch on day 14.

Following PLAN-A-AGENT-CONTROL.md §2 ("Reality check — 5–6 person plan, 2 people"), we apply the §20.3 fallback ladder _up front_ rather than in panic. This decision is written in the repo (README.md "Scope" section) so judges see honest scoping.

## Decision

We pre-emptively cut the following items from the master plan:

| Item                                                | Master Plan                                   | Our Scope                                                                | Rationale                                                                                              |
| --------------------------------------------------- | --------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| Bench sites                                         | 4 (ShopLite, GovPortal, MailLite, ClinicDesk) | **2 + 1 stretch** — ShopLite, GovPortal; ClinicDesk only if time permits | ClinicDesk earns its place only as B's canvas/OCR proof. Two sites are sufficient for demo + ablation. |
| Vision detector (P10)                               | Full datagen + training                       | **Stretch only. Cut by default.**                                        | 3 days of B's time. Explain-or-redact keeps leakage at 0 without it (PLAN.md §28, cut #6).             |
| NER (P8)                                            | Fine-tune DistilBERT                          | **Off-the-shelf ONNX NER, no training**                                  | Training is 2.5 days B does not have.                                                                  |
| OCR (P9)                                            | PP-OCRv5 via raw ORT-Web                      | **tesseract.js first**, PP-OCRv5 as upgrade                              | Integration in hours instead of days.                                                                  |
| Ablations                                           | A1–A7                                         | **A1, A6, A7 only**                                                      | PLAN.md §20.1 already sanctions this. Three points still make a frontier.                              |
| Real-site suite                                     | 2–3 public pages                              | **Cut**                                                                  | Pure risk, zero demo value.                                                                            |
| Full-page stitch, per-site memory, signed audit log | Stretch                                       | **Cut, do not discuss again**                                            |                                                                                                        |

### Never Cut (Non-negotiable)

Per PLAN-A §2 and PLAN.md §20.3:

- Egress gate
- Canary harness
- Deferred value binding (vault references)
- Leakage-zero guarantee

These four _are_ the project.

## Consequences

- **Positive:** `main` stays buildable and demoable at every commit. The team can deliver a working vertical slice by Day 5 (MVP) and a privacy-proven system by Day 8.
- **Negative:** Some evaluation rows in the ablation table will be empty. We will state this explicitly in the presentation: "We scoped honestly; here is what we measured, here is what we cut, and why."
- **Risk:** If B's perception pipeline (OCR/NER/vision) takes longer than expected, we fall back to DOM-only + deterministic recognizers, which still yields a working privacy boundary.
