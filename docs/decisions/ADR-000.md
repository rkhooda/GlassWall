# ADR-000: Conservative Scope and Fallbacks

**Date:** 2024-08-28
**Status:** Accepted
**Deciders:** GlassWall maintainers

## Context

The project combines browser automation, local perception, and privacy enforcement. A
large feature set would make the security boundary harder to reason about and would
increase the chance of an unverified fail-open path. Scope is therefore reduced up
front, with conservative fallbacks that preserve privacy when a capability is absent.

## Decision

We pre-emptively cut the following items from the master plan:

| Item                                                | Master Plan                                   | Our Scope                                                                | Rationale                                                                                              |
| --------------------------------------------------- | --------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| Bench sites                                         | Many production-like pages | **Three local sites** — ShopLite, GovPortal, ClinicDesk | Deterministic pages make privacy and browser behavior reproducible. |
| Vision detector                                      | Full visual-PII detector                      | **Not included.**                                                        | Explain-or-redact masks unexplained image regions without adding a fail-open dependency.             |
| NER                                                 | Fine-tuned model                              | **Off-the-shelf ONNX NER, no training**                                  | Keeps the model pipeline reproducible and local.                                                                  |
| OCR                                                 | Large vision stack                            | **Tesseract.js first**                                                   | Smaller integration surface and a clear conservative timeout path.                                                                  |
| Ablations                                           | Every possible combination                   | **Focused privacy and fusion studies**                                  | Measures the decisions that affect the boundary without creating a second product.                              |
| Real-site suite                                     | Broad production coverage                     | **Not part of the benchmark**                                           | External pages change and cannot provide stable ground truth.                                                                            |
| Full-page stitch, per-site memory, signed audit log | Stretch                                       | **Cut, do not discuss again**                                            |                                                                                                        |

### Never Cut (Non-negotiable)

The following remain non-negotiable:

- Egress gate
- Canary harness
- Deferred value binding (vault references)
- Leakage canary and fail-closed behavior

These four _are_ the project.

## Consequences

- **Positive:** the main branch stays buildable and the security boundary remains small enough to test.
- **Negative:** benchmark coverage is narrower than arbitrary web automation.
- **Risk:** If local perception is unavailable, utility drops because unexplained content is withheld. Privacy is preserved.
